## Validated post-route results

8-way / SDP+URAM / GRASP / `INCLUDE_VICTIM=0` / `DATABANK_SDP=1`.

| Cache | Target MHz | Knobs                              | WNS (ns) | Achievable MHz | Status |
|---|---:|---|---:|---:|---|
| 512 KB | 250 | baseline                            | -0.022 | 249 | ✓ essentially MET; one route reseed closes |
| 512 KB | **300** | **tuned (DBL=3, WIR=1, aggressive)** | **+0.127** | **312** | **✓ MET (best of the three boards)** |
| 1 MB   | 300 | tuned                                | -0.140 | 288 | misses by 12 MHz; 34-URAM cascade is the binding path |

Tuned-knob combination: `DB_LATENCY=3 SDP_WRITE_INPUT_REG=1
PLACE_DIRECTIVE=ExtraNetDelay_high PHYS_DIRECTIVE=AggressiveExplore
ROUTE_DIRECTIVE=AggressiveExplore`.

## Multi-CU deployment arithmetic

| Configuration             | URAM | %URAM | BRAM | %BRAM |
|---|---:|---:|---:|---:|
| 16 CU × 512 KB / 8w / SDP | 256  | 13 %  |  80  |  4 %  |
| 32 CU × 512 KB            | 512  | 26 %  | 160  |  8 %  |
| 16 CU × 1 MB              | 544  | 28 %  |  32  |  2 %  |
| 32 CU × 1 MB              | 1088 | **56 %** | 64 |  3 %  |
| 16 CU × 2 MB              | 1056 | **55 %** | 32 |  2 %  |

U55C has the best URAM-headroom story for large multi-CU deployments —
32 caches × 1 MB leaves 44 % URAM free vs U250's 15 %.

## Why pick U55C

| Reason | Detail |
|---|---|
| HBM2 backing | 460 GB/s aggregate sustains the worst-case miss stream behind the L2 array. |
| Production silicon | No ES clock-uncertainty penalty (unlike V80). |
| URAM headroom | 1936 URAMs leaves significant budget after a 32-CU L2 array. |
| Same family as U250 | Identical UltraScale+ HBM speed file → ports cleanly between the two. |

## Recommended configuration for graph-accelerator deployments

```sv
l2_cache #(
    .POLICY              (GRASP),
    .LINES               (1024),     // 512 KB at LINE_W=16
    .LINE_W              (16),
    .WAYS                (8),
    .BLOCK_W             (32),
    .DB_LATENCY          (3),        // tuned for 300 MHz
    .INCLUDE_VICTIM      (0),
    .DATABANK_SDP        (1),
    .SDP_WRITE_INPUT_REG (1)         // tuned for 300 MHz
    // ADDR_RANGE_L / ADDR_RANGE_H per system map
) u_cache ( /* AXI */ );
```

Vivado synth/PnR knobs:
```bash
PERIOD_NS=3.333 DB_LATENCY=3 SDP_WRITE_INPUT_REG=1 \
  PLACE_DIRECTIVE=ExtraNetDelay_high \
  PHYS_DIRECTIVE=AggressiveExplore \
  ROUTE_DIRECTIVE=AggressiveExplore \
  PNR=1 ./syn/vivado/u55c_synth.sh
```

## Caveats

- 1 MB at 300 MHz hits ~288 MHz post-route — for hard 300 MHz lock at
  1 MB, U250 is the better pick (closes at 302 MHz).
- Production silicon — no ES-specific timing surprises.
- HBM2 controller is not part of this cache; integrators must route
  the master AXI port to the HBM IP through the NoC.
